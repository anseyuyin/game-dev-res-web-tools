# 开发规范

本文件说明如何为「游戏开发资源工具集」新增一个工具。核心只有一句话：

> **一个工具 = 一个自包含的 `.html` 文件。**

---

## 一、硬性规则

### 1. 单一文件

- 每个工具是 `tools/` 下的一个 `.html` 文件。
- 不在 `tools/` 下创建 `.js` / `.css` / 图片等附属文件——工具的样式、脚本、图标、数据必须全部内联在 HTML 中。
- 确需演示用素材时，使用 Base64 Data URI 内联，或让用户在页面上自行选择文件。

### 2. 零依赖

- 禁止引用外部 CDN、外链字体、外链脚本或图片。
- 禁止使用需要构建的框架（React/Vue 打包产物等）或需安装的运行时。
- 允许使用浏览器原生 API：`Canvas`、`WebGL`、`Web Audio`、`File API`、`Web Worker`（通过 `Blob` 内联创建）、`IndexedDB`、`localStorage` 等。

### 3. 本地优先

- 不向任何服务器上传用户数据，不发起业务网络请求。
- 所有解析、转换、生成都在浏览器本地完成。
- 可以使用 `fetch` 读取自身目录下的文件（仅在 `http://` 下可用），但不要依赖它作为主流程。

### 4. 单一入口

- 所有工具必须在 [`tools/tools_index.html`](../tools/tools_index.html) 的 `TOOLS` 数组中登记，否则不会被检索到。
- 同时更新 [工具索引.md](工具索引.md) 的清单表格。

### 5. 命名规范

- 文件名使用 kebab-case，语义化，例如：
  - ✅ `texture-atlas-packer.html`
  - ✅ `sprite-sheet-slicer.html`
  - ❌ `tool1.html`、`新建工具.html`、`TexturePacker.html`
- 以 `_` 开头的文件（如 `_template.html`）视为内部文件，不登记进索引。

---

## 二、新增工具的步骤

```powershell
# 1. 复制模板
Copy-Item tools\_template.html tools\your-tool-name.html

# 2. 实现功能（编辑 tools\your-tool-name.html）

# 3. 登记到 tools\tools_index.html 的 TOOLS 数组

# 4. 更新 docs\工具索引.md

# 5. 检查与提交
git add .
git commit -m "feat: 新增 <工具名>"
```

## 三、页面结构约定

为了让所有工具观感统一，建议沿用模板中的结构：

```
<header>   面包屑（返回工具索引） + 标题 + 一句话说明
<main>
  ├─ 输入区   ：参数表单 / 文件拖放区
  ├─ 输出区   ：结果预览、统计信息、下载按钮
  └─ 日志区   ：处理过程的可读日志（成功 green / 警告 yellow / 失败 red）
<footer>   一行说明
```

### 推荐的配色变量

模板已内置一套深色主题变量，直接复用即可：

```css
:root{
  --bg:#0d1117; --bg-soft:#161b22; --bg-card:#1a2029;
  --border:#2a3340; --border-soft:#222a35;
  --text:#e6edf3; --text-dim:#9aa7b4; --text-faint:#6b7683;
  --accent:#4ea1ff; --accent-soft:rgba(78,161,255,.14);
  --ok:#3fb950; --warn:#d29922; --err:#f85149;
  --radius:12px;
}
```

### 索引登记字段

```js
{
  id:   "your-tool-name",        // 必填，唯一，用于收藏存储
  name: "工具中文名",             // 必填
  desc: "一句话说明工具用途。",     // 必填，参与搜索
  file: "your-tool-name.html",   // 必填，相对 tools_index.html
  icon: "🧩",                    // 建议填，一个 emoji
  tags: ["美术", "纹理"]          // 建议填，2~4 个标签
}
```

> ⚠️ `id` 一旦发布就视为稳定标识，重命名会让已有用户的收藏失效。

## 四、用户体验检查清单

提交前请逐项确认：

- [ ] 双击 HTML 文件（`file://` 协议）即可正常使用，无需本地服务器。
- [ ] 断网状态下功能完整。
- [ ] 页面在窄屏（手机宽度）下不发生横向滚动或元素重叠。
- [ ] 大文件 / 大量数据处理时不阻塞 UI（必要时用 `Web Worker` 或分片 + `requestAnimationFrame`）。
- [ ] 出错时给出明确的中文提示，而不是静默失败或只在控制台报错。
- [ ] 提供「重置」入口，方便反复使用。
- [ ] 已在 `tools_index.html` 的 `TOOLS` 数组登记，且 `file` 路径可正常打开。
- [ ] 已更新 `docs/工具索引.md`。
- [ ] 文件中没有残留 `TODO`、调试 `console.log` 与无用示例代码。

## 五、常见问题

**Q：工具需要读取用户选择的文件，怎么做？**
A：用 `<input type="file">` 或拖放 + `FileReader` / `File.arrayBuffer()`，不要试图直接读取本地路径。

**Q：想生成文件让用户下载？**
A：用 `URL.createObjectURL(new Blob([...]))` 配合 `<a download>`（模板中已封装 `downloadBlob()`）。

**Q：能不能放多个工具在一个 HTML 里？**
A：不行。工具箱的价值在于「一个链接解决一件事」，多合一工具会让索引和分享都变得混乱。

**Q：工具之间要共享代码怎么办？**
A：复制粘贴。宁可重复，也不要引入共享文件——那会破坏「单文件可独立分享」这一前提。

**Q：需要第三方算法实现（例如 WebP 编码）？**
A：把实现内联进 HTML；如果体积过大，先评估是否换用浏览器原生 API（`canvas.toBlob('image/webp')` 等）。
