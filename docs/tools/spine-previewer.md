# 🦴 Spine 动画预览与调试器

> 上级索引：[工具索引](../工具索引.md) ｜ 索引 id：`spine-previewer`
> 工具文件：[`tools/spine-previewer.html`](../../tools/spine-previewer.html)（单文件，无任何外部依赖）

**一句话**：把本地目录里所有 Spine 资源扫成一张列表，双击即可预览播放；滚轮缩放、拖时间轴停留、显示部件层级 / 网格 / 骨骼，并可直接拖骨骼或拖网格顶点做姿态与形变调试。

---

## 1. 解决什么问题

游戏项目里的 Spine 资源散落在很多子目录中，文件名常是 `xxx-pro.json` / `xxx.skel` / `xxx.atlas` / 多张分页贴图。想快速回答下面这些问题，过去只能在 Spine 编辑器里逐个打开，或用引擎跑起来看：

- 这个动作循环接缝对不对？某一帧的形变是不是崩了？
- 某个部件为什么看不见（附件时间轴 / 颜色 alpha / 混合模式 / 裁剪）？
- 这条 IK 链到底有没有够到目标？网格权重在哪些骨骼上？
- 交付的是 JSON 还是二进制？图集缺贴图吗？

这个工具不修改任何资源，只做「本地只读预览 + 调试」，双击即可用，不需要引擎工程、不需要装 Spine、不上传任何文件。

## 2. 功能一览

| 分组 | 能力 |
| --- | --- |
| **目录与扫描** | 用 `showDirectoryPicker` 绑定一个本地目录（路径缓存在浏览器本地，下次打开可一键恢复，浏览器仅要求重新授权一次）；递归扫描子目录，自动把「骨架 + 图集 + 图集分页贴图」配对成一个资源并列出。骨架与图集**不同名也能配对**：先找同目录同名图集，再按名称打分（`hero-ess.json` ↔ `hero.atlas`、`1-weight-and-mass-balls-ess.json` ↔ `1-weight-and-mass.atlas`），分数接近时用「图集区域名是否出现在骨架里」交叉核对；同一目录有多个图集时，资源行里会出现下拉框可手动指定。缺图集 / 缺贴图 / 自动配对的图集、以及本工具尚不支持的二进制版本都会打标提示；支持按名称过滤、按文件夹分组，若「仅可用资源」把列表清空会给出可点击的「显示全部资源」提示 |
| **加载** | **双击**列表项加载：先彻底清理上一个预览（释放纹理与显存、清空姿态与形变调试），再加载新资源；也支持直接拖入文件夹 / 文件，或 `?asset=` URL 直链（http 环境） |
| **播放** | 动画下拉切换、播放 / 暂停、循环、速度 0.05×–3×、逐帧步进（按骨架 fps）、回到起点 / 跳到结尾；进度条拖动即**停留在该时刻**（拖动自动暂停）；事件时间轴触发时写入日志 |
| **皮肤** | 多皮肤资源（换装 / mix-and-match）会显示「皮肤」下拉框，可切换皮肤并即时重解析附件（列表里显示每个皮肤的附件数量），切回默认皮肤同样一键完成 |
| **视图** | 滚轮以光标为锚点缩放、拖动平移、适配视图 / 1:1、可切换棋盘 / 深灰 / 浅灰 / 绿幕 / 洋红 / 纯黑底色与世界坐标网格 |
| **显示与调试** | 骨骼 / 网格线框 / 包围盒 / 贴图 / 骨骼名 / 坐标轴 / 裁剪 独立开关；部件层级（绘制顺序）与骨骼层级两棵树，点击选中并在视口高亮；👁 切换部件显示；双击部件 / 骨骼把视图对准它。调试叠加层与角色**严格同平面**：叠加层绘制缓冲区按「视口 CSS 尺寸 × dpr」设置，与 WebGL 绘制缓冲区一一对应，因此骨骼 / 网格 / 包围盒在任何缩放与窗口尺寸下都贴合角色，不会被 CSS 拉伸错位 |
| **拖拽调试** | 「骨骼」模式：左键拖关节＝旋转、**Shift** ＋拖＝平移、双击关节＝重置该骨骼；「网格顶点」模式：选中网格部件后出现顶点手柄，拖动即改当前帧形变；姿态与形变都叠加在动画之上，可一键清空；检查器里还能直接输入角度 / 位移精确调试 |
| **检查器** | 选中骨骼：局部角度 / 位移 / 缩放 / 剪切 / 世界坐标 / 世界角度 / 长度 / transformMode，及当前调试偏移；选中部件：骨骼、附件名与类型、混合模式、槽色 × 附件色、暗色（双色染色）、图集区域与分页、顶点数与是否带权重、序列帧进度、裁剪结束槽、路径闭合与匀速 |
| **渲染** | WebGL2；纹理按预乘 alpha 上传，正常 / 叠加 / 正片叠底 / 屏幕 四种混合、贴图分页切换、裁剪附件（scissor 实现）、区域旋转（0/90）、序列帧换图、权重网格、形变、骨架自带尺寸适配 |
| **格式兼容** | JSON 导出：3.8 / 4.0 / 4.1 / 4.2 全覆盖，**4.3 按 4.2 规则解析并额外支持 4.3 的统一 `constraints` 数组与变换约束 `properties` 属性映射**（含 3.8 的平铺曲线、4.x 的绝对曲线、序列帧、链接网格、4.2 的单轴时间轴与 `inherit`）；二进制 `.skel`：4.0 / 4.1 完整，4.2 / 3.8 部分支持，**4.3 的二进制字节布局有变、暂不支持**（扫描阶段就会标出来并提示改用同名 JSON，不会静默读错） |

## 3. 典型工作流

1. **绑定目录** → 首次点「📁 选择文件夹」，工具扫描并列出全部 Spine 资源（下次打开点「恢复该目录」即可）。
2. **双击资源** → 自动清理旧预览并加载，视图自动适配；缺贴图或缺图集会在日志里给出中文原因。
3. **看动作** → 选动画、播放；发现异常就拖进度条停在可疑时刻，用 `◀|` `|▶` 逐帧看。
4. **查部件** → 左侧「部件层级」按绘制顺序列出，点选高亮；怀疑被裁剪或混合模式问题就在检查器里核对；👁 逐个隐藏排查遮挡。
5. **调试姿态** → 切「骨骼」模式拖关节（Shift 平移），或用检查器输入精确角度；「↺ 清空姿态调试」还原。
6. **调形变** → 暂停后切「网格顶点」模式，选中网格部件拖顶点观察权重与形变；「↺ 清空网格形变」还原。

## 5. 已知限制

- **Spine 版本**：JSON 导出支持 **3.8 / 4.0 / 4.1 / 4.2**（用 126 个官方示例逐字段交叉校验通过）；**4.3 的 JSON** 结构是 4.2 的超集，工具会按 4.2 规则解析并额外支持 4.3 的新形态（统一 `constraints` 数组、`source`/`slot` 字段名、变换约束的 `properties` 属性映射、IK 的 `scaleYMode`），日志会给出「比已知版本新」的提示。**二进制 `.skel`**：**4.0 / 4.1 完整**（官方示例全部解析且字节完全对齐），**4.2** 与 **3.8** 部分支持（例如 4.2 的 `snowglobe` / `sack` / `cloud-pot` 等可正常加载；解析不了的文件会给出中文原因，绝不静默读错字节流）；**4.3 的二进制布局有变，暂不支持**——扫描时只读文件头即可判定，列表里直接打红标并提示改用同名 JSON。3.6 / 3.7 的老资源会明确报「不支持的版本」。
- **骨骼时间轴的取值语义**（关键）：官方 JSON 里 `rotate` / `translate` / `shear` 关键帧存的是**相对 setup 的增量**，`scale` 存的是**相对 setup 的乘数**，不是绝对值。工具严格按官方 `getRelativeValue` / `getScaleValue` 求解（单个轴的 `translateX/Y`、`scaleX/Y`、`shearX/Y` 时间轴同理）。如果把关键帧当绝对值应用，所有骨骼都会回落到 0 / 缩放回落到 1，整只骨架向原点塌陷——这正是修复前 4.3 样例「人物折叠」的根因。关键帧里没写 `x` 或 `y` 时按增量 0 处理（即回到 setup 值），这也是官方行为。
- **物理约束（4.2 / 4.3 `physics`）不做模拟**：相关骨骼按动画与其它约束的结果显示，日志会提示数量。
- **部分颜色时间轴不参与播放**：4.2 的 `rgb` / `alpha` / `rgb2`（只改单个颜色通道的时间轴）会被解析并存放，但暂未接入播放（完整 `rgba` / `rgba2` 正常）。骨骼的单轴时间轴（`translateX/Y`、`scaleX/Y`、`shearX/Y`）与 4.2 的 `inherit` 时间轴**已参与播放**。
- **颜色 / 染色（tint）已与官方对齐**：单色染色按 `skeletonColor × slotColor × attachmentColor` 求值；**双色染色（`slot.dark`，暗色）** 按官方 `slot.darkColor != null` 判定并走双色着色器，公式与 spine-webgl 的 `newTwoColoredTextured` 一致（`light.rgb` 含 alpha、`dark.rgb = slot.darkColor.rgb × alpha`）。
- **`skeleton.color`（骨架级颜色）未参与渲染**：官方渲染链是 `skeletonColor × slotColor × attachmentColor`，本工具只用后两项。官方样例里没有资源用到骨架级颜色，因此实测无差异；若拿到用到它的资源需补上这一环。
- **约束求值顺序**：按 `order` 升序、同序时 IK → 变换 → 路径，每个约束后重算世界变换；被约束改动过的骨骼会沿父链校正世界矩阵，避免子骨骼用到过期矩阵。多级链式约束的极端情况下仍可能与官方运行时存在差异（见下条）。
- **变换约束的两套语义**：4.2 及更早用「偏移 + mix」的经典语义；4.3 的 `properties` 属性映射按官方公式 `to.offset + (源值 + from.offset) * to.scale` 求值（含 `clamp`）。但官方是「矩阵权威」模型（约束直接改写骨骼矩阵，本地 rotation 与矩阵可以解耦），本工具是「本地量权威」模型；当**源骨骼带剪切（shear）**时，旋转映射会有几度量级偏差，并可能沿骨骼链放大（官方 `alien-pro` 的 eye / eye-stalk 系列属于这一类，偏差约 3～25 单位）。无约束的官方样例（各 `*-ess`）实测偏差 ≤ 1 单位。
- **路径约束**为按弧长分布的近似实现（`tangent` / `chainScale` 旋转模式的尖端与缩放细节做了简化），官方 `*-pro` 样例中带路径约束的（`vine-pro`、`celestial-circus-pro`、`hero-pro` 等）会有明显偏差，属于实现完备度问题而非时间轴语义问题。
- **IK** 双骨骼求解按官方公式实现（含非均匀缩放、softness、compress/stretch 分支）；偏差主要来自上游骨骼的微小差异被 IK 放大，官方 `raptor-pro` 这类长 IK 链样例实测偏差可达几十单位。
- **裁剪附件**用视口 scissor（屏幕轴对齐矩形）近似，不做路径级精细裁剪；不支持嵌套裁剪。
- **非均匀缩放 / 剪切下的双骨骼 IK** 走官方公式，但骨骼剪切会按官方语义在 IK 结果里归零。
- **时间轴拖动编辑形变**：形变是逐帧数据，动画播放时会覆盖你的拖动结果，建议先暂停再调。
- **序列帧附件**支持骨架自带的 sequence（区域附件 + `sequence` 块形式），网格序列帧不换 UV。
- **超大目录**：默认最多扫描 40000 个文件、对 JSON 骨架做前 800 字节探针识别（上限 3000 个），超出会提示；单个网格顶点数超过 4000 的附件会被跳过绘制。图集配对只在「同目录有多个图集且名称对不上」时才会读整份骨架 JSON 做区域名交叉核对（每个骨架至多一次），二进制骨架只读前 512 字节拿版本号。
- 所有解析都在浏览器本地完成，**不上传、不修改任何资源文件**。

## 7. 调试 API（`window.SPINE`）

页面暴露了一个自动化友好的接口，方便做批量验证或二次集成：`status()`、`resources()`、`loadUrl()`、`loadEntries()`、`loadDemo()`、`selectResource()`、`play()/pause()/setTime()/setAnimation()/setSpeed()`、`view()/setView()/fit()`、`setToggles()`、`selectBone()/selectSlot()/selection()`、`poseBone()/overrides()/resetPose()/resetDeform()`、`ikError()`（IK 末端误差与指向误差自检）、`attachmentInfo()`、`sampleScreen()`、`renderNow()`。`?asset=<url>` 参数还支持在 http 环境下直链加载某个骨架（按与目录扫描同一套打分逐个尝试 `.atlas` 候选名，可用 `&atlas=` 指定）。
