# 🦴 Spine 动画预览与调试器

> 上级索引：[工具索引](../工具索引.md) ｜ 索引 id：`spine-previewer`
> 工具文件：[`tools/spine-previewer.html`](../../tools/spine-previewer.html)（单文件，无任何外部依赖）

**一句话**：把本地目录里所有 Spine 资源扫成一张列表，双击即可预览播放；滚轮缩放、拖时间轴停留、显示部件层级 / 网格 / 骨骼，并可直接拖骨骼或拖网格顶点做姿态与形变调试。

---

## 1. 解决什么问题

游戏项目里的 Spine 资源散落在很多子目录中，文件名常是 `xxx-pro.json` / `xxx.skel` / `xxx.atlas` / 多张分页贴图。想快速回答下面这些问题，过去只能在 Spine 编辑器里逐个打开，或用引擎跑起来看：

- 这个动作循环接缝对不对？某一帧的形变是不是崩了？
- 某个部件为什么看不见（附件时间轴 / 颜色 alpha / 混合模式 / 裁剪）？
- 这条 IK 链到底有没有够到目标？网格权重在哪些骨骼上？
- 交付的是 JSON 还是二进制？图集缺贴图吗？

这个工具不修改任何资源，只做「本地只读预览 + 调试」，双击即可用，不需要引擎工程、不需要装 Spine、不上传任何文件。

## 2. 功能一览

| 分组 | 能力 |
| --- | --- |
| **目录与扫描** | 识别骨架后缀 `.json` / `.skel.json` / `.skel` / `.skel.bytes` / `.bytes` / `.bin`（`.skel.bytes` / `.bytes` / `.bin` 会读文件头判断内容：二进制走二进制解析，被改名成 `.bytes` 的 JSON 文本按 JSON 解析，兼顾 Unity TextAsset 的导出习惯）；用 `showDirectoryPicker` 绑定一个本地目录（路径缓存在浏览器本地，下次打开可一键恢复，浏览器仅要求重新授权一次）；递归扫描子目录，自动把「骨架 + 图集 + 图集分页贴图」配对成一个资源并列出。骨架与图集**不同名也能配对**：先找同目录同名图集，再按名称打分（`hero-ess.json` ↔ `hero.atlas`、`1-weight-and-mass-balls-ess.json` ↔ `1-weight-and-mass.atlas`），分数接近时用「图集区域名是否出现在骨架里」交叉核对；同一目录有多个图集时，资源行里会出现下拉框可手动指定。缺图集 / 缺贴图 / 自动配对的图集、以及本工具尚不支持的二进制版本都会打标提示；支持按名称过滤、按文件夹分组，若「仅可用资源」把列表清空会给出可点击的「显示全部资源」提示 |
| **加载** | **双击**列表项加载：先彻底清理上一个预览（释放纹理与显存、清空姿态与形变调试），再加载新资源；也支持直接拖入文件夹 / 文件，或 `?asset=` URL 直链（http 环境） |
| **播放** | 动画下拉切换、播放 / 暂停、循环、速度 0.05×–3×、逐帧步进（按骨架 fps）、回到起点 / 跳到结尾；进度条拖动即**停留在该时刻**（拖动自动暂停）；事件时间轴触发时写入日志 |
| **皮肤** | 多皮肤资源（换装 / mix-and-match）会显示「皮肤」下拉框，可切换皮肤并即时重解析附件（列表里显示每个皮肤的附件数量），切回默认皮肤同样一键完成 |
| **视图** | 滚轮以光标为锚点缩放、拖动平移、适配视图 / 1:1、可切换棋盘 / 深灰 / 浅灰 / 绿幕 / 洋红 / 纯黑底色与世界坐标网格 |
| **显示与调试** | 骨骼 / 网格线框 / **路径** / 包围盒 / 贴图 / 骨骼名 / 坐标轴 / 裁剪 独立开关；视口工具条上的骨骼 / 网格 / **路径** / 包围盒按钮**高亮＝开启、压暗＝关闭**，一眼可辨（也可按 `B` / `M` / `U` 或勾选右栏复选框）；**路径**（工具条 **〰**）画的是 Spine 的**路径附件**：它本身没有贴图、官方运行时也不渲染，只是路径约束用的一条**复合贝塞尔控制线**，这里按官方几何把每段三次贝塞尔**细分**后画成**绿色虚线**（细分数随缩放自适应，放大不会露出折角）——因此它与「网格」开关无关，网格没开也照样显示，不想要就关掉该开关或到部件层级里 👁 隐藏这一个插槽；裁剪附件的轮廓同样按曲线细分，但它跟随「网格」开关；工具条上还有一个 **Mesh 权重** 开关（**◔**，或 `?weights=1`）：打开后在**骨骼线下方**叠加一层更宽、**不透明**的**彩色骨骼**示意线（每根骨骼一种颜色，按 `bones` 下标取黄金角散列的色相；不透明是为了让示意线颜色与顶点扇形图的颜色完全一致），并在**带权重网格的每个顶点**处画一个圆，圆内按影响该顶点的骨骼切成**扇形**——扇形颜色＝对应骨骼的示意线颜色、扇形角度 ∝ 权重占比（从 12 点方向顺时针铺开），圆的尺寸大于顶点的方形手柄且**垫在手柄之下**，所以选中网格部件拖顶点时两者互不遮挡；**没有被任何 mesh 顶点引用（权重 > 0）的骨骼不画彩色示意线**（这类骨骼不驱动任何网格，上色会让人误以为它参与权重，其骨骼线仍按原样显示）；选中网格部件时彩色示意线收窄到**与该网格顶点相关**的骨骼，选中骨骼时不再按部件收窄（选中的那根若没被任何顶点引用则仍然没有颜色）；不带权重的网格、路径 / 裁剪 / 包围盒附件的顶点不画扇形图；部件层级（按绘制顺序）与骨骼层级两棵树，点击选中并在视口高亮（部件之间只有绘制顺序、没有父子关系，所以部件表不做折叠）；**两棵树都与视口点选联动**——在视口里点中骨骼 / 部件后，对应面板会**自动滚动到那一行并闪烁高亮**（面板收着时自动展开，过滤词挡住目标时自动清空），重新渲染（选中、调试刷新、改可见性）也不会再把列表滚回顶部；**骨骼层级按父子关系递归展开，每个节点可单独折叠 / 展开**（点行首 `▸` / `▾`，**Alt** ＋点击＝连整棵子树；右上角 `⇕` 一键全展开 / 全折叠，图标随状态切换 `⊞` / `⊟`），视口点选骨骼时还会**自动展开它的所有祖先**（Unity 层级面板同款联动）；👁 切换部件显示；双击部件 / 骨骼把视图对准它。**同一位置连续点击＝逐层遍历**（Unity 同款）：光标下常常叠着好几根骨骼 / 好几个部件，单击选到的是**最上层**，在**原地继续点**就依次往下选一层，遍历完一轮回到最上层**循环**（骨骼之间、部件之间、骨骼与部件之间都算；点选位置一变、缩放 / 平移了视图、或从两棵树里改了选中，都会重新从最上层开始；按在 Gizmo 上但**没拖动**也算一次点选，所以在关节点上照样能这样翻）。**骨骼显示关闭时视口不参与骨骼拾取**：点视口任意位置都不会选中看不见的骨骼（只会命中部件或取消选中），双击也不会重置骨骼，而是回落到「适配视图」。调试叠加层与角色**严格同平面**：叠加层绘制缓冲区按「视口 CSS 尺寸 × dpr」设置，与 WebGL 绘制缓冲区一一对应，因此骨骼 / 网格 / 包围盒在任何缩放与窗口尺寸下都贴合角色，不会被 CSS 拉伸错位 |
| **拖拽调试** | 「骨骼」模式：左键拖关节＝旋转、**Shift** ＋拖＝平移、双击关节＝重置该骨骼；选中网格部件后出现顶点手柄，拖动即改当前帧形变（顶点手柄随「网格线框」开关，关掉网格线则手柄一并隐藏且不可拖）；姿态与形变都叠加在动画之上，可一键清空；检查器里还能直接输入角度 / 位移精确调试 |
| **检查器** | 选中骨骼：局部角度 / 位移 / 缩放 / 剪切 / 世界坐标 / 世界角度 / 长度 / transformMode，及当前调试偏移；选中部件：骨骼、附件名与类型、混合模式、槽色 × 附件色、暗色（双色染色）、图集区域与分页、顶点数与是否带权重、序列帧进度、裁剪结束槽、路径闭合与匀速。每个属性行都带悬浮说明；**混合模式与颜色可直接在检查器里改**：下拉切换 normal / additive / multiply / screen，取色器 + alpha 滑杆改槽色，改动**即时生效并叠加在动画之上**（覆盖值只存在于运行时，不改资源数据），带 `（已改）` 标记与逐项 ↺ 还原，或随「清空姿态调试」一起还原 |
| **IK 约束调试** | 选中的骨骼只要参与 IK（是链条里的骨骼，或 IK 的目标骨骼），检查器下半部分就会列出它参与的每条 IK 约束：标注当前骨骼的角色（**链条骨骼** / **目标骨骼**）、链条顺序、目标骨骼与求值顺序（骨骼树里这类骨骼标 `IK` / `IK 目标`）。卡片上可直接调 **混合 mix**（0–1）、**柔和 softness**（0–100）、**弯曲方向**（正向 / 反向＝`bendPositive`）、**压缩 `compress`**、**拉伸 `stretch`**、**统一缩放 `uniform`**，每项都有悬浮说明。覆盖值写在**每帧动画之后**，因此即使该动画带 IK 时间轴也不会被冲掉；未改动的参数会跟随动画逐帧刷新显示。改过的约束标「**已改**」并高亮边框，卡片上的 **↺** 单独还原这一条，「↺ 清空姿态调试」会连同骨骼偏移一起还原——覆盖只在运行时，**不修改资源数据** |
| **变换约束调试** | 选中的骨骼只要参与变换约束（是被驱动骨骼，或是约束的源骨骼），检查器下半部分就会列出它参与的每条变换约束：标注角色（**被驱动骨骼** / **源骨骼**）、被驱动链条、源骨骼、求值顺序，并给出该约束的**映射表**（源属性 → 目标属性，含 `offset` / `scale`）与来源格式（`4.3 properties` 或 `≤4.2 local/relative`；旧格式的映射表由经典语义推导而来，卡片上会注明）。可调 **六个 mix**（`mixRotate` / `mixX` / `mixY` / `mixScaleX` / `mixScaleY` / `mixShearY`，滑杆 + 数字框双向同步）、四个行为开关 **`localSource` / `localTarget` / `additive` / `clamp`**，以及展开后的**六个偏移量**（`rotation` / `x` / `y` / `scaleX` / `scaleY` / `shearY`），每项都有悬浮说明。骨骼树里这类骨骼标 `变换` / `变换源`。覆盖同样写在**每帧动画之后**（压过变换约束时间轴），未改动的参数逐帧跟随；**↺** 单独还原一条，「↺ 清空姿态调试」全部还原，**不修改资源数据** |
| **路径约束调试** | 选中的骨骼只要参与路径约束（是沿路径排布的骨骼，或是目标插槽所在的骨骼），检查器下半部分就会列出它参与的每条路径约束：标注角色（**被驱动骨骼** / **目标骨骼**）、驱动链条、**目标插槽**（官方 JSON 的 `target` / 4.3 的 `slot`）、当前**路径附件**（是否闭合 / 是否匀速）与求值顺序。可在运行时切换 **位置模式**（fixed / percent）、**间距模式**（length / fixed / percent / proportional）、**旋转模式**（tangent / chain / chainScale），并调 **位置 `position`**、**间距 `spacing`**、**三个 mix**（`mixRotate` / `mixX` / `mixY`，滑杆 + 数字框双向同步）与 **旋转偏移 `offsetRotation`**，每项都有悬浮说明。骨骼树里这类骨骼标 `路径` / `路径目标`。资源里标了 `skin`（skinRequired）而当前皮肤未启用时，卡片会提示「官方不会对它求值」；覆盖写在**每帧动画之后**（压过路径约束时间轴），**↺** 单独还原，「↺ 清空姿态调试」全部还原，**不修改资源数据** |
| **渲染** | WebGL2；纹理按预乘 alpha 上传，正常 / 叠加 / 正片叠底 / 屏幕 四种混合、贴图分页切换、裁剪附件（scissor 实现）、区域旋转（区域附件按官方语义处理 0 / 90；网格附件按图集 `rotate` 的 0 / 90 / 180 / 270 全角度映射 UV，与官方 `MeshAttachment.computeUVs` 逐分支一致）、序列帧换图、权重网格、形变、骨架自带尺寸适配 |
| **格式兼容** | JSON 导出：**3.6 / 3.7 / 3.8 / 4.0 / 4.1 / 4.2 / 4.3**（3.6 / 3.7 与 3.8 同构，按 3.8 规则解析并兼容 `deform` / `paths` 旧键名；4.3 额外支持统一的 `constraints` 数组与变换约束 `properties` 属性映射）；二进制 `.skel`：**3.6 / 3.8 / 4.0 / 4.1 / 4.2 / 4.3 全部支持**（官方样例 17/18、20/20、20/20、21/21、28/28、44/44 整文件字节对齐），其中 4.3 的 44 个样例还与官方 `spine-core 4.3` 运行时**逐次读取序列完全一致**、骨骼 / 插槽 / 约束 / 动画的解析结果**逐字段数值一致**（解析不了会给出中文原因 + 出错字节偏移，不会静默读错） |

## 3. 典型工作流

1. **绑定目录** → 首次点「📁 选择文件夹」，工具扫描并列出全部 Spine 资源（下次打开点「恢复该目录」即可）。
2. **双击资源** → 自动清理旧预览并加载，视图自动适配；缺贴图或缺图集会在日志里给出中文原因。
3. **看动作** → 选动画、播放；发现异常就拖进度条停在可疑时刻，用 `◀|` `|▶` 逐帧看。
4. **查部件** → 左侧「部件层级」按绘制顺序列出，点选高亮（视口里被上层挡住的部件，在**同一个位置连点**即可逐层翻到它，见「显示与调试」）；怀疑被裁剪就在检查器里核对，怀疑混合模式 / 颜色问题可直接在检查器里改（混合模式下拉、取色器 + alpha）当场看效果；👁 逐个隐藏排查遮挡。
5. **调试姿态** → 切「骨骼」模式拖关节（Shift 平移），或用检查器输入精确角度；「↺ 清空姿态调试」还原。
6. **查 IK** → 点骨骼树里带 `IK` / `IK 目标` 标记的骨骼，检查器里会出现 `🎯 IK 约束` 卡片：把 **mix** 拉到 0 看「没有 IK 时动画原本的姿势」，或在目标超出骨骼链长度（够不到）时打开 **拉伸** / 调 **柔和**，观察关节如何取舍；确认完点卡片上的 ↺ 或「↺ 清空姿态调试」还原。
7. **查变换约束** → 点骨骼树里带 `变换` / `变换源` 标记的骨骼，检查器里会出现 `🧭 变换约束` 卡片：核对**映射表**（源属性 → 目标属性、offset / scale）与来源格式；动画把某个方向压到 `mix = 0` 时把 mix 拉回 0–1 即可当场看到约束的作用，调 `offsetX / offsetY` 可以验证世界分支是按源骨骼的本地轴施加偏移；确认完点卡片上的 ↺ 或「↺ 清空姿态调试」还原。
8. **查路径约束** → 点骨骼树里带 `路径` / `路径目标` 标记的骨骼，检查器里会出现 `🪢 路径约束` 卡片：把 **mixRotate** 拉到 0 看「只按路径摆位置、不改朝向」，或切换 **间距模式**（length / percent / proportional）观察骨骼沿路径的疏密变化；调 **位置 / 间距** 可以让链条滑到路径的另一段；确认完点卡片上的 ↺ 或「↺ 清空姿态调试」还原。
9. **调形变** → 暂停后切「网格顶点」模式，选中网格部件拖顶点观察权重与形变；「↺ 清空网格形变」还原。

## 5. 已知限制

- **Spine 版本**：JSON 导出支持 **3.6 / 3.7 / 3.8 / 4.0 / 4.1 / 4.2**（3.8+ 用 126 个官方示例逐字段交叉校验通过；3.6 / 3.7 与 3.8 同构，按 3.8 规则解析并兼容 `deform` / `paths` 旧键名，已用官方 `spine-ts 3.6` 运行时对 9 个官方 3.6 / 3.7 样例逐项对照一致）；**4.3 的 JSON** 结构是 4.2 的超集，工具会按 4.2 规则解析并额外支持 4.3 的新形态（统一 `constraints` 数组、`source`/`slot` 字段名、变换约束的 `properties` 属性映射、IK 的 `scaleYMode`），日志会给出「比已知版本新」的提示。**二进制 `.skel`**：**3.6 / 3.8 / 4.0 / 4.1 / 4.2 / 4.3 全部支持**（官方样例 3.6 17/18、3.8 20/20、4.0 20/20、4.1 21/21、4.2 28/28、4.3 44/44 整文件字节对齐，且结构/时间轴与同目录 JSON 导出逐项一致）。**4.3 的验证口径**：44 个官方 4.3 样例与官方 `spine-core 4.3.13` 运行时①**逐次读取序列完全一致**（读取种类、偏移、顺序三项全等）、②骨骼（含 4.3 调整过顺序的 `inherit` / `length`）、插槽、IK / 变换 / 路径 / 物理约束（含映射表 offset / max / scale）、事件、动画的解析结果**逐字段数值一致**、③每条约束时间轴的**作用对象（按名字）与帧值一致**、④逐动画取样时刻的**骨骼世界变换一致**（相对偏差 ≤ 2e-3），并与同目录 JSON 导出做结构交叉校验（44/44）。**3.7 的二进制布局未做字节级验证，会明确报「不支持的版本」**（3.6 已支持），4.4+ 同样明确报错并建议改用同名 JSON。**已知遗留**：官方 3.6 样例里 `alien/alien-pro.skel` 的形变时间轴段仍会多读 4 字节（17/18），其余 3.6 样例全部字节对齐。
- **4.3 的约束时间轴下标要换算**（易错点）：4.3 的动画里，IK / 变换 / 路径 / 物理 / slider 时间轴引用的都是**统一 `constraints` 数组**的下标（官方 4.3 的 `skeleton.constraints[this.constraintIndex]`），而本运行时的 `IkConstraintTimeline` / `TransformConstraintTimeline` / `PathConstraintTimeline` 是按**分类型数组**取值（与 JSON 解析器的 `indexOf` 一致）。二进制解析器在读出下标后会立刻换算成分类型下标；不换算就会让时间轴驱动错误的约束（或越界后整条不生效），表现为**被 IK / 路径约束摆位的部件跑到别处或不显示**。
- **骨骼时间轴的取值语义**（关键）：官方 JSON 里 `rotate` / `translate` / `shear` 关键帧存的是**相对 setup 的增量**，`scale` 存的是**相对 setup 的乘数**，不是绝对值。工具严格按官方 `getRelativeValue` / `getScaleValue` 求解（单个轴的 `translateX/Y`、`scaleX/Y`、`shearX/Y` 时间轴同理）。如果把关键帧当绝对值应用，所有骨骼都会回落到 0 / 缩放回落到 1，整只骨架向原点塌陷——这正是修复前 4.3 样例「人物折叠」的根因。关键帧里没写 `x` 或 `y` 时按增量 0 处理（即回到 setup 值），这也是官方行为。
- **旋转的「最短路径」语义按版本区分（4.0 是分水岭）**：Spine **4.0 之前**（本工具的 3.6 / 3.8 二进制、3.8 JSON）关键帧之间**总是走最短路径**——官方在插值前把相邻帧的角度差折到 −180°~180°（`r -= (16384 - ((16384.499999999996 - r / 360) | 0)) * 360`，3.6 / 3.8 / 4.0 的差异见 spine-ts `RotateTimeline.apply`）：`0° → 350°` 实际只转 **−10°**，所以 3.8 里要做整圈旋转**必须补中间关键帧**（例如 0 / 120 / 240 / 360）。**4.0 及以后**取消了这个行为，直接在两个关键帧数值之间插值（`0° → 350°` 就转 +350°），此时写 0 / 360 两个关键帧才是「转一圈」。工具按文件版本自动选择：≤3.8 时贝塞尔控制点按折过的差值换算、求值按最短路径插值、并把结果折回 −180°~180°（本地 rotation 与检查器读数都与官方一致）；4.0+ 走原来的插值路径，逐位不变（已用改动前的实现自比 62443 个采样点验证差异为 0）。已用**官方 3.8 运行时**（3.8 分支构建产物）对 20 个官方 3.8 样例的 JSON 与 `.skel` 逐条 rotate 时间轴、逐点比对：修复前 1335 个采样点不一致 → 修复后 **0 个**（线性 / 阶梯段 26685 个对照点全部一致），剩余偏差只出现在贝塞尔段且 ≤ 2.7°，属于本工具解真实三次贝塞尔、官方 3.8 走 10 段折线采样带来的既有近似，与旋转语义无关。
- **物理约束（4.2 / 4.3 `physics`）不做模拟**：相关骨骼按动画与其它约束的结果显示，日志会提示数量。
- **部分颜色时间轴不参与播放**：4.2 的 `rgb` / `alpha` / `rgb2`（只改单个颜色通道的时间轴）会被解析并存放，但暂未接入播放（完整 `rgba` / `rgba2` 正常）。骨骼的单轴时间轴（`translateX/Y`、`scaleX/Y`、`shearX/Y`）与 4.2 的 `inherit` 时间轴**已参与播放**。
- **单轴时间轴要写进对应的通道**（已修的坑）：官方 4.0+ 的 `translateX` / `translateY` 等是**独立的类**，每帧只有 1 个数值；本工具统一用双通道类表示，所以这个数值必须落在它自己的通道（x → 第 1 列、y → 第 2 列），另一列补 0，**贝塞尔曲线也要落在同一列**。早期实现固定把单通道数值写进第 1 列，于是 `translateY` / `scaleY` / `shearY` 的数值落进 x 列、y 列因 `Float32Array` 写入 `undefined` 变成 **NaN** —— 表现就是**部件位置显示 `NaN`、整个部件不显示**；同一处还把单轴时间轴当成「只存数据」的 `TimelineStore`（JSON 侧），导致 4.x 的 `translateX/Y` 完全不参与播放。3.8 / 4.0 / 4.1 的官方样例不含单轴时间轴，4.2 有 2 个文件、4.3 有 12 个文件受影响（共 107 条时间轴），现已全部修正。
- **单轴时间轴的求值只能写自己那一轴**（已修的坑）：补 0 的那一列**绝不能被写回骨骼**。同一根骨骼常常同时有 `translatex` 与 `translatey` 两条时间轴（4.3 的 `6-arcs-pro` 里 `ball-main` 就是），而本工具用双通道类表示单轴时间轴；如果 apply 时把补 0 的第二列也写进去，后应用的那条时间轴就会把另一轴**复位到 setup** —— 表现是「动画里某个轴的位移被固定死、只有另一个轴能动」（用户报的「X 轴位移锁死」就是这个）。现在 `TranslateTimeline` / `ScaleTimeline` / `ShearTimeline` 按解析期写入的 `singleAxis` 标记只改对应的一列，JSON 与 `.skel` 两条路径都做过与官方运行时的逐时刻对拍（`6-arcs-pro` 的 `ball-main`：修复前预览器 X 行程 0.00 / 官方 5031.83，修复后两者逐点一致）。
- **曲线记录按「段 × 属性」存，不能按段号误删**（已修的坑）：`CurveTimeline.propCurves` 的键是 `seg * propertyCount + prop`。当解析器把整段置为线性 / 阶梯、或写段级共用曲线时（不传 `prop`），旧实现执行 `propCurves.delete(seg)`；单属性时间轴的键恰好等于段号所以看不出问题，但**多属性时间轴会误删别的段的记录**（2 通道 translate 的 `18*2+1 = 37` 正好等于段号 37）。被删掉的段会静默退化成线性插值：官方 `6-arcs-pro.skel` 的 `ball-main.translatey` 就是在 t=3.0 处差了 18.9 单位。现在统一走 `clearPropCurves(seg)`，只清该段自己的键。
- **曲线列号不能传错**（已修的坑）：4.x 颜色时间轴（`rgba` / `rgb` / `rgba2`）的贝塞尔是**逐分量** 4 个数；旧实现把颜色分量数组当成列号偏移传进 `readCurve4`，键变成 `"0.5,0.2,0.1,10"` 这种字符串，per 分量曲线永远取不到（官方 `coin-pro` 的 `animation/coin-front-texture.rgba` 修复前后插槽颜色差 6.8e-3 → 5.8e-7）。IK 时间轴同理：4.2 / 4.3 的 `flags & 0x80` 段有 **2 条独立曲线（mix / softness）**，旧实现只把第一条写成段级共用曲线、把 softness 的 4 个数丢掉，softness 因此套用 mix 的手柄，IK 角度能差出上百单位（`spineboy-pro` 的 `walk/front-leg-ik` 修复前 `front-shin` 偏差 221 单位 → 修复后与官方一致）。另外 IK 的 `bendDirection` 官方是**按段取原值、不插值**，用 `getValue(time, 2)` 插值会让恒为 −1 的 bend 被 mix 的手柄拉成正数、整段 IK 反向，现已改为按段取值。
- **双通道时间轴的曲线必须逐通道写**（已修的坑）：4.0+ 的贝塞尔控制点是「每通道 4 个数」。早期实现只把通道 0 的 4 个数当成**整段共用曲线**、把通道 1..n 的 4 个数直接丢掉，于是 translate / scale / shear 的第 2 通道会套用第 1 通道的手柄 —— 两端关键帧都是 0 时，段中间仍会被手柄拉出非 0 值（`windmill` 的 `bush1.shearY` 因此变成 -3.09）。现在按通道 `setBezierAt` 写入。
- **颜色 / 染色（tint）已与官方对齐**：单色染色按 `skeletonColor × slotColor × attachmentColor` 求值；**双色染色（`slot.dark`，暗色）** 按官方 `slot.darkColor != null` 判定并走双色着色器，公式与 spine-webgl 的 `newTwoColoredTextured` 一致（`light.rgb` 含 alpha、`dark.rgb = slot.darkColor.rgb × alpha`）。
- **`skeleton.color`（骨架级颜色）未参与渲染**：官方渲染链是 `skeletonColor × slotColor × attachmentColor`，本工具只用后两项。官方样例里没有资源用到骨架级颜色，因此实测无差异；若拿到用到它的资源需补上这一环。
- **底色四边形的顶点必须按「周长顺序」给**（已修的坑）：棋盘（以及其他图案）底色画在 canvas **内部**，这样 additive / multiply / screen 才有正确的不透明 destination；底色四边形固定用索引 `0,1,2 / 0,2,3` 切两个三角形，因此 4 个顶点**必须沿矩形周长依次排列**（左上 → 右上 → 右下 → 左下）。早期实现写成「左上 → 右上 → 左下 → 右下」，顶点序列其实是**自交的「蝴蝶结」**：`(0,1,2)` 覆盖 `{y ≥ x}`、`(0,2,3)` 覆盖 `{x + y ≤ 0}`，两者并集恰好漏掉右侧楔形 `{x ≥ |y|}`（约占视口 1/4）；漏掉的像素 alpha 恒为 0，透出 `#viewportWrap` 的 `#0a0d12`，表现就是**选了棋盘底色后视口右侧多出一块黑色三角**（用户报的这个问题），纯色底色走 `gl.clear` 所以只有棋盘会犯。现在改为周长顺序，并且在叠图案之前先用棋盘主色 `gl.clear` 铺一层不透明底（`gl.clear` 不受混合影响、写进去的 alpha 恒为 1）——即使将来几何再出错，也只会是一块纯色而不再是黑洞。验证：对 6 种底色 × 3 种缩放/平移状态**整帧读回帧缓冲**断言「alpha 全 255 + 棋盘恰好两种颜色且占比 45%~55% + 首格与 22px 格宽不变」，把顶点顺序退回蝴蝶结即失败（漏空 57134px / 24.9%）。
- **约束求值顺序**：按 `order` 升序、同序时 IK → 变换 → 路径，每个约束后重算世界变换；被约束改动过的骨骼会沿父链校正世界矩阵，避免子骨骼用到过期矩阵。多级链式约束的极端情况下仍可能与官方运行时存在差异（见下条）。
- **变换约束按官方 4.3 的「源属性 → 目标属性」模型求值**：六个源 / 目标属性、`localSource` / `localTarget` / `additive` / `clamp`、`from.offset` / `to.offset` / `to.max` / `to.scale` 与 `offsetRotation…offsetShearY` 都与官方逐项对齐。≤4.2 的 `local` / `relative` + 六个偏移在解析期**归一化成等价的映射表**（`local` ⇔ `localSource` + `localTarget`，`relative` ⇔ `additive`），并保留旧格式在本地旋转 / 剪切上的 ±180° 最短路径折叠。官方是「矩阵权威」模型（约束直接改写骨骼矩阵），本工具是「本地量权威」模型，因此世界分支写完矩阵后会调用 `Bone.updateAppliedTransform()`（官方同名函数的移植）把矩阵精确折回本地量再重算——Normal 变换模式下两者互为逆运算，结果与官方一致。已用官方 spine-core **4.0 / 4.1 / 4.2 / 4.3** 运行时对合成用例逐项对照（4.0 / 4.1 / 4.2 各 56 例、4.3 的 properties 形态 26 例全部一致）；官方样例中 alien 的最大世界坐标偏差由 **386.8 → 4.3**、celestial-circus **402.4 → 24.5**、spineboy **52.2 → 9.6**、owl 保持 0。**修正后仍可能出现的可见差异来自长 IK 链**（官方 `raptor-pro` 这类样例，上游骨骼的微小差异会被 IK 放大）与形变时间轴的细微差别。
- **路径约束按官方 `PathConstraint` 逐条实现**：目标按**插槽**解析（官方 JSON 的 `target` / 4.3 的 `slot` 都写插槽名——旧实现用 `findBone` 找，找不到就整条约束静默失效，这正是「路径约束没起效」的根因）；骨骼沿路径的**贝塞尔曲线**求点与切线（官方 `computeWorldPositions` 的匀速 / 非匀速两条分支逐字移植），三种间距模式、三种旋转模式、`mixRotate` / `mixX` / `mixY` 与 `offsetRotation` 与官方一致；约束写完世界矩阵后标记「矩阵权威」，让随后的一次世界变换重算跳过这些骨骼（官方运行时同样不做这次重算），避免反解近似把结果磨掉。**验证**：把官方运行时在「关闭路径约束」下算出的姿态（骨骼本地量 + 路径约束运行值 + 形变）整份喂给本工具、再只跑路径约束，官方带路径约束的样例（4.1 的 hero / vine / tank / stretchyman / mix-and-match）逐骨骼世界坐标误差 **≤ 0.0001**。
- **`skinRequired`（资源里的 `"skin": true`）按官方语义生效**：约束或骨骼标了 `skin` 时，只有当前皮肤的 `bones` / `constraints` 列表包含它才求值（hero 的 `weapon-morningstar` 路径约束、`weapon-morningstar` 骨骼都是这种，官方在默认皮肤下**不应用**该约束）。旧实现忽略这个标记，会多算一条约束把骨骼拽到完全不同的位置。
- **IK** 双骨骼求解按官方公式实现（含非均匀缩放、softness、compress/stretch 分支）；偏差主要来自上游骨骼的微小差异被 IK 放大，官方 `raptor-pro` 这类长 IK 链样例实测偏差可达几十单位。
- **IK 参数调试的单位**：检查器里的 **柔和 softness 按资源原值直接作用**（官方 3.8–4.2 的 JSON 与 4.1 的二进制里都写成 0–100 的百分比，例如官方 `spineboy-pro` 的 `run` 里是 10 / 14.8 / 48.2 / 61.4，与官方 4.1 运行时的取值方式一致），所以滑杆的 0–100 与资源数值一一对应，不做换算；覆盖值只作用于预览，与「清空姿态调试」一起还原。
- **裁剪附件**用视口 scissor（屏幕轴对齐矩形）近似，不做路径级精细裁剪；不支持嵌套裁剪。
- **非均匀缩放 / 剪切下的双骨骼 IK** 走官方公式，但骨骼剪切会按官方语义在 IK 结果里归零。
- **时间轴拖动编辑形变**：形变是逐帧数据，动画播放时会覆盖你的拖动结果，建议先暂停再调。
- **序列帧附件**支持骨架自带的 sequence（区域附件 + `sequence` 块形式），网格序列帧不换 UV。
- **超大目录**：默认最多扫描 40000 个文件、对 JSON 骨架做前 800 字节探针识别（上限 3000 个），超出会提示；`.skel.bytes` / `.bytes` / `.bin` 额外读前 512 字节嗅探内容（二进制还是 JSON 文本）；单个网格顶点数超过 4000 的附件会被跳过绘制。图集配对只在「同目录有多个图集且名称对不上」时才会读整份骨架 JSON 做区域名交叉核对（每个骨架至多一次），二进制骨架只读前 512 字节拿版本号。
- 所有解析都在浏览器本地完成，**不上传、不修改任何资源文件**。

## 7. 调试 API（`window.SPINE`）

页面暴露了一个自动化友好的接口，方便做批量验证或二次集成：`status()`、`resources()`、`loadUrl()`、`loadEntries()`、`loadDemo()`、`selectResource()`、`play()/pause()/setTime()/setAnimation()/setSpeed()`、`view()/setView()/fit()`、`setToggles()`、`selectBone()/selectSlot()/selection()`、`poseBone()/overrides()/resetPose()/resetDeform()`、`ikError()`（IK 末端误差与指向误差自检）、`ikParams()`（每条 IK 的当前值与覆盖值）、`setIkParam(name, patch)` / `resetIk(name)`（写入 / 清除 IK 参数覆盖，`name` 省略时清空全部）、`tcParams()`（每条变换约束的当前值、覆盖值与映射表）、`setTcParam(name, patch)` / `resetTc(name)`（写入 / 清除变换约束参数覆盖，字段为 `mixRotate…mixShearY`、`localSource/localTarget/additive/clamp`、`offsetRotation…offsetShearY`）、`pathParams()`（每条路径约束的运行值、覆盖值、目标插槽 / 路径附件与皮肤启用状态）、`setPathParam(name, patch)` / `resetPath(name)`（写入 / 清除路径约束参数覆盖，字段为 `position`、`spacing`、`mixRotate`、`mixX`、`mixY`、`offsetRotation`、`positionMode`、`spacingMode`、`rotateMode`）、`attachmentInfo()`、`candidatesAt(x, y)`（光标处可选目标的列表，顺序＝连点遍历顺序）、`pickAt(x, y)`（模拟一次视口点选：同一位置连续调用会依次返回下一层目标、遍历完循环；会推进连点状态但不改选中）、`sampleScreen()`、`renderNow()`。`?asset=<url>` 参数还支持在 http 环境下直链加载某个骨架（按与目录扫描同一套打分逐个尝试 `.atlas` 候选名，可用 `&atlas=` 指定）。
