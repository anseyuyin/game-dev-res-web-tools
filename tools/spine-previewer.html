🦴 Spine 动画预览与调试器

轻量的 Spine 资源预览 / 播放 / 调试工具：纯本地运行，不上传任何文件，支持 JSON 与 二进制（.skel / .skel.bytes） 两种导出，WebGL2 渲染。
上次使用的目录（已缓存）：
也可以直接把 文件夹、或 骨架 + .atlas + 贴图 拖进窗口。
目录路径会缓存在浏览器本地，下次打开可一键恢复（需重新授权一次，这是浏览器的安全限制）。
  • 扫描目录内所有 Spine 资源（含子目录），双击列表项即可加载预览。
  • 滚轮缩放、拖拽平移；播放 / 暂停 / 拖时间轴停留任意时刻。
  • 显示部件层级、网格线框、骨骼，并可直接拖拽骨骼或拖拽网格顶点调试形变。

使用说明

1. 加载资源
  • 点「📁 选择文件夹」授权一个目录，工具会递归扫描其中所有 Spine 资源并列举在左侧。
  • 双击列表项：先清理当前预览（释放纹理与显存），再加载该资源。
  • 资源识别规则：骨架文件（.json / .skel / .skel.bytes / .skel.json / .bytes / .bin）＋ 图集（.atlas，及图集里的贴图）＝ 一个资源。.skel.bytes / .bytes / .bin 会读文件头判断内容：二进制按二进制解析，被改名的 JSON 文本按 JSON 解析（Unity 的 TextAsset 常见做法）。
  • 骨架与图集不同名也能配对：先找同目录同名图集，再按名称打分（如 hero-ess.json ↔ hero.atlas、1-weight-and-mass-balls-ess.json ↔ 1-weight-and-mass.atlas），必要时用「图集区域名是否出现在骨架里」交叉核对；自动配对的资源会标「图集推断」。缺图集 / 缺贴图的资源仍会列出并标红，取消勾选「仅可用资源」即可看到。
  • 同目录有多个图集时，资源行右侧会出现图集下拉框，可手动指定用哪个图集（切换后立即重新配对并重载预览）。
  • 二进制 .skel 的版本在扫描时就会读取：本工具不支持的版本（如 3.7 或 4.4+）会直接打红标并提示改用同名 JSON，而不是点开才报错。
  • 也可以直接拖入文件：骨架 + 图集 + 贴图一起拖入时按名字自动配对。
  • Chrome / Edge 之外的浏览器（或不支持文件夹选择器时）可用「📂 兼容选择」（webkitdirectory）。
2. 播放与时间轴
  • 下拉框切换动画；▶ / ⏸ 播放暂停；进度条可拖动并在该时刻停留（拖动时自动暂停）。
  • 速度 0.05×–3×；可循环；⏮ ◀| |▶ ⏭ 逐帧步进。
3. 显示与 Gizmo 变换
  • 骨骼 / 网格线框 / 包围盒 / 贴图 / 骨骼名 / 裁剪 均可独立开关；视口工具条上的骨骼 / 网格 / 包围盒按钮高亮＝开启、压暗＝关闭。
  • 骨骼显示关闭时，视口里点不到骨骼：看不见的骨骼不参与拾取，点视口任意位置都只会命中部件（或取消选中），也不会因双击而重置骨骼。要选中 / 拖拽骨骼，先用工具条的 🦴 或 B 打开骨骼显示。
  • 视口左上角的竖排工具条（Unity 风格）切换交互类型：位移 / 旋转 / 缩放 会显示不同的 Gizmo，鼠标悬停在按钮上会弹出该工具的操作说明。点击骨骼或部件即选中，Gizmo 中心随之移动到该对象上。
  • 位移：拖动绿色（Y）/ 红色（X）箭头按轴位移，拖中心方块在 XY 平面自由位移。
  • 旋转：拖动 Gizmo 圆环绕关节旋转。
  • 缩放：拖动轴端方点按轴缩放，拖中心方点整体缩放。缩放的 Gizmo 会随骨骼朝向一起旋转（Unity 的 Local 轴模式）：红色轴＝骨骼自身 X 轴（沿骨骼长度方向），绿色轴＝骨骼自身 Y 轴，与骨骼 scaleX / scaleY 一一对应。位移与旋转仍按世界轴 / 整体圆环显示。
  • 变换结果叠加在动画之上、以「调试偏移」保存，可一键清空（Shift+R 或按钮）。选中部件时，变换作用于该部件所属的骨骼（与 Spine 编辑器一致）。
  • 顶点编辑默认开启：选中网格部件即显示顶点手柄，无需切换工具，拖动即可修改当前帧的网格形变（建议先暂停）。Gizmo 手柄命中优先，其余位置都交给顶点手柄。顶点手柄跟随「网格线框」开关：关掉网格线后手柄一并隐藏、也不再可拖。
  • 部件层级列表里 👁 可隐藏部件，双击部件＝把视图对准它；双击骨骼＝重置该骨骼姿态（需骨骼显示开启，关闭时双击视口＝适配视图）。
  • 检查器里显示的都是「当前帧的实际值」：骨骼的位置 / 旋转 / 缩放 / 剪切 / 世界坐标与角度、部件所属骨骼的变换、附件 / 类型 / 混合 / 颜色 / 序列帧索引等，都会随动画播放逐帧刷新——面板只更新数值、不重建 DOM，所以不会打断你正在拖动的滑杆、颜色选择器，也不会让面板滚动位置跳回顶部。附件随动画时间轴切换时，「图集区域 / 顶点数 / 序列帧 / 裁剪到 / 路径」这些行会自动出现或隐藏。
  • 调试偏移（含 Gizmo 拖动结果）也实时同步：上方「调试偏移」数值与下方输入框会跟着变；正在编辑（获得焦点）的输入框不会被覆盖，失去焦点后再同步成规范小数值。
4. IK 约束调试
  • 在视口或骨骼树里选中一根骨骼：只要它参与 IK（是链条里的骨骼，或是 IK 的目标骨骼），检查器下半部分就会出现 🎯 IK 约束 卡片，列出它参与的每条 IK，并标注当前骨骼的角色（链条骨骼 / 目标骨骼）、链条顺序、目标骨骼与求值顺序。骨骼树里这类骨骼也会标 IK / IK 目标。
  • 卡片上可直接调 混合 mix（0–1）、柔和 softness（0–100）、弯曲方向（正向 / 反向＝bendPositive）、压缩 compress、拉伸 stretch、统一缩放 uniform，每一项都有悬浮说明。
  • 改动即时生效，并且压过动画：覆盖值写在每帧动画之后，所以即使该动画有 IK 时间轴，你调的值也不会被冲掉。未改动的参数会跟随动画实时刷新显示（例如 running 动作里柔和的逐帧变化）。
  • 改过的约束在卡片上标「已改」并高亮边框，点卡片右上角的 ↺ 单独还原这一条；「显示与调试」里的 ↺ 清空姿态调试 会把骨骼偏移与 IK 覆盖一起还原。覆盖只在运行时，不会修改资源文件。
  • 典型用法：把 mix 调到 0 看「没有 IK 时动画原本的姿势」，或在目标超出骨骼链长度（够不到）时打开 拉伸 / 调 柔和 观察关节如何取舍。
5. 变换约束调试
  • 在视口或骨骼树里选中一根骨骼：只要它参与变换约束（是被驱动骨骼，或是约束的源骨骼），检查器下半部分就会出现 🧭 变换约束 卡片。骨骼树里这类骨骼会标 变换 / 变换源。
  • 卡片列出映射表（源属性 → 目标属性，含 offset / scale）、源骨骼、求值顺序，并标出这条约束来自 4.3 的 properties 还是 ≤4.2 的 local / relative（旧格式的映射表由经典语义推导而来，卡片上会注明）。
  • 可直接调六个 mix（mixRotate / mixX / mixY / mixScaleX / mixScaleY / mixShearY，滑杆 + 数字框双向同步）、四个行为开关 localSource / localTarget / additive / clamp，以及偏移量（旋转 / 位移 / 缩放 / 剪切，点「偏移量 ▾」展开）。每项都有悬浮说明。
  • 改动即时生效并压过动画：覆盖值写在每帧动画之后，所以即使该动画带变换约束时间轴也不会被冲掉；未改动的参数会跟随动画逐帧刷新显示。
  • 改过的约束标「已改」并高亮边框，卡片右上角 ↺ 单独还原这一条，「↺ 清空姿态调试」会连同骨骼偏移与 IK 覆盖一起还原。覆盖只在运行时，不会修改资源文件。
  • 典型用法：动画里把某个方向压到 mix = 0 时（例如 alien 的 death 会把眼睛约束全部关掉），把 mix 拉回 1 就能立刻看到约束的作用；给 offsetX / offsetY 一个值可以直观看出「世界分支按源骨骼本地轴施加偏移」的效果。
6. 路径约束调试
  • 在视口或骨骼树里选中一根骨骼：只要它参与路径约束（是沿路径排布的骨骼，或是目标插槽所在的骨骼），检查器下半部分就会出现 🪢 路径约束 卡片，并标注当前骨骼的角色（被驱动骨骼 / 目标骨骼）。骨骼树里这类骨骼会标 路径 / 路径目标。
  • 卡片显示链条、目标插槽（官方 JSON 的 target / 4.3 的 slot）、当前的路径附件（是否闭合 / 是否匀速）与求值顺序，并能在运行时切换 位置模式（fixed / percent）、间距模式（length / fixed / percent / proportional）、旋转模式（tangent / chain / chainScale）。
  • 可直接调 位置 position、间距 spacing、三个 mix（mixRotate / mixX / mixY，滑杆 + 数字框双向同步）与 旋转偏移 offsetRotation，每项都有悬浮说明。
  • 改动即时生效并压过动画：覆盖值写在每帧动画之后，所以即使该动画带路径约束时间轴也不会被冲掉；未改动的参数会跟随动画逐帧刷新显示。
  • 资源里标了 skin（skinRequired）而当前皮肤没有启用该约束时，卡片会给出提示——官方运行时对这种约束不求值，本工具同样跳过。
  • 改过的约束标「已改」并高亮边框，卡片右上角 ↺ 单独还原这一条，「↺ 清空姿态调试」会连同其它覆盖一起还原。覆盖只在运行时，不会修改资源文件。
  • 典型用法：把 mixRotate 拉到 0 看「只按路径摆位置、不改朝向」的效果；把 间距模式切到 percent / proportional 观察骨骼沿路径的疏密变化；调 位置 / 间距 让链条滑到路径的另一段。

7. 兼容性与限制
  • JSON 导出支持 Spine 3.6 / 3.7 / 3.8 / 4.0 / 4.1 / 4.2 / 4.3（4.3 另支持统一的 constraints 数组与变换约束的 properties 属性映射；3.6 / 3.7 与 3.8 同构，按 3.8 规则解析并兼容 deform / paths 两个旧键名，解析细节会在日志里提示）；二进制 .skel 的 3.6 / 3.8 / 4.0 / 4.1 / 4.2 / 4.3 全部支持：官方样例 3.6 17/18、3.8 20/20、4.0 20/20、4.1 21/21、4.2 28/28、4.3 44/44 整文件字节对齐，其中 4.3 的 44 个样例还与官方 spine-core 4.3 运行时逐次读取序列完全一致、骨骼 / 插槽 / 约束 / 动画的解析结果逐字段数值一致（解析不了会给出中文原因，不会静默读错）。渲染使用 WebGL2。
  • 二进制 .skel 的版本在扫描时会读文件头判定：3.6 没有共享字符串表、骨骼没有 skinRequired、IK 约束没有 softness、普通皮肤没有 bones/constraints 列表，这些差异都按版本分支处理；3.6 / 3.8 的曲线控制点是归一化比例且写在本帧数据之后，与 4.0+ 的绝对控制点写法不同。
  • 3.6 / 3.7 的 JSON 与 3.8 同构，差别只有动画里的键名：附件（形变）时间轴叫 deform（3.8 起叫 attachments，而且 3.6 少一层 —— 附件名下面直接就是帧数组）、路径约束时间轴叫 paths（3.8 起叫 path）；其余 3.8 才出现的字段（IK 的 softness / compress / stretch、皮肤自带 bones / constraints、序列帧等）按缺省处理。已用官方 spine-ts 3.6 运行时对 9 个官方 3.6 / 3.7 样例做骨骼 / 插槽 / 皮肤 / 附件 / 动画逐项对照，全部一致。
  • 4.3 的二进制与 4.2 的字节布局不同，本工具按版本分别解析：骨骼的 inherit 挪到了 length 之前、nonessential 的骨骼多了 iconSize/iconRotation、有顶点权重时多一个条目数 varint、五类约束合并成带 type 字节的 constraints 数组（IK 的 uniform 换成 scaleYMode、path 的 skinRequired 并入 flags、transform 改成「源属性 → 目标属性」映射表、新增 slider）、mesh 附件多一段 timelineSlots、linked mesh 多一个 sourceIndex、clipping 多 convex/inverse 两位，动画里多了 slider 时间轴、draw order folder 时间轴与动画自带颜色。另外 4.3 的约束时间轴用「统一 constraints 数组」的下标引用约束（官方 skeleton.constraints[i]），而本运行时按分类型数组取值，解析时已按下标换算——换算错会让 IK / 路径约束驱动到别的骨骼上，表现为这些部件跑到别处或不显示。
  • 骨骼 rotate / translate / shear 关键帧是相对 setup 的增量、scale 是相对 setup 的乘数（与官方一致）；关键帧没写 x / y 时按增量 0 处理。
  • 旋转的「最短路径」按版本区分：Spine 4.0 之前（本工具的 3.6 / 3.8 二进制、3.8 JSON）关键帧之间总是走最短路径——官方把相邻帧的角度差折到 −180°~180°，所以 0° → 350° 实际只转 −10°（3.8 里要做整圈旋转必须补中间关键帧，例如 0 / 120 / 240 / 360）；4.0 及以后取消了这个行为，直接在两个关键帧数值之间插值（0° → 350° 就转 +350°）。工具按文件版本自动选择，≤3.8 时连贝塞尔控制点也按折过的差值换算，求值结果与官方 3.8 运行时逐点一致。
  • 物理约束（physics）暂不模拟，相关骨骼会保持动画本身的结果。
  • 变换约束按官方 4.3 的「源属性 → 目标属性」模型求值（六个 from / to、localSource / localTarget / additive / clamp、offset 与 clamp 区间都与官方逐项对齐；≤4.2 的 local / relative / 六个偏移在解析期归一化成等价的映射表，并保留旧格式在本地旋转 / 剪切上的 ±180° 最短路径折叠）。已用官方 4.0 / 4.1 / 4.2 / 4.3 运行时逐用例对照通过。
  • 路径约束按官方 PathConstraint 逐条实现（目标按插槽解析、沿贝塞尔曲线求点与切线、三种间距模式 / 三种旋转模式 / 三个 mix 一致）；把官方运行时在「关闭路径约束」下算出的姿态整份喂给本工具再只跑路径约束，官方带路径约束的样例（hero / vine / tank / stretchyman / mix-and-match）世界坐标逐骨骼误差 ≤ 0.0001。剩余可见差异来自长 IK 链与形变时间轴的细微差别。
  • 检查器里的 IK / 变换 / 路径约束参数覆盖写在每帧动画之后，只影响预览；柔和 softness 按资源原值直接作用（官方 3.8–4.2 的 JSON / 二进制里都是 0–100 的百分比写法，与官方 4.1 运行时的取值方式一致），所以滑杆的 0–100 与资源里的数值一一对应，工具不做换算。
  • 需要 file:// 或 http:// 打开；不支持文件夹选择器时用兼容选择。
  • 直接用 ?asset= 参数可在 http 环境下直链加载某个骨架（自动按名称逐个尝试 .atlas 候选名，可用 &atlas= 指定）。
